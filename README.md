# 🏁 TEMU TESLA

**1~4명이 키보드를 나눠 눌러서, 로드스터 한 대를 함께 몰고 9,000m 도시를 돌파하는 온라인 협동 3D 게임**입니다.

- 바퀴 4개와 제트 배출구 4개, 합쳐서 **키 8개(Q W A S / E R D F)** 로 차 한 대를 조종합니다.
- 1명이면 8개를 혼자, 2명이면 4개씩, 4명이면 2개씩 나눠 맡습니다. (**3명은 불가**)
- 도로 말고 아무 데나 닿으면 폭발! 체크포인트에서 다시 시작하며 10구간 · 체크포인트 40개를 완주하면 끝납니다.
- 서버가 물리 계산을 전부 맡고(서버 권위), 브라우저는 three.js로 그리기만 합니다. 설치 파일 없이 **PC 브라우저**(Chrome·Edge 최신 버전 권장)면 됩니다.
- 모바일(터치 화면)은 키보드가 필요해서 지원하지 않습니다 (접속하면 안내 화면만 나옵니다).

## 1. 압축 풀기

1. 받은 `temu-tesla.zip` 을 우클릭 → **압축 풀기**(Windows: "모두 압축 풀기", Mac: 더블클릭).
2. 풀린 폴더 안에 `package.json`, `server`, `client`, `shared`, `tools`, `README.md` 가 보이면 정상입니다.
   - 폴더 안에 같은 이름의 폴더가 한 겹 더 있으면 한 단계 더 들어가세요. **`package.json` 이 보이는 폴더가 "프로젝트 폴더"** 입니다.

## 2. (선택) 내 컴퓨터에서 먼저 실행해 보기

> 건너뛰어도 됩니다. 배포 전에 "내 컴퓨터에서 되는지" 보고 싶을 때만 하세요.

1. **Node.js** 를 설치합니다: <https://nodejs.org> 에서 **LTS** 버전 (22 권장, 18.19 이상이면 동작).
2. 터미널(Windows: 시작 메뉴에서 "PowerShell", Mac: "터미널")을 열고 프로젝트 폴더로 이동합니다.
   ```bash
   cd 압축푼폴더경로/temu-tesla
   npm install
   npm start
   ```
   - 처음 `npm install` 은 1~2분 걸립니다 (three.js, express, socket.io 를 내려받음). 인터넷이 필요합니다.
   - `[Temu Tesla] 서버 시작: http://localhost:3000` 이 보이면 성공입니다.
3. 브라우저에서 <http://localhost:3000> 을 엽니다. 이름 입력 → **방 만들기** → **게임 시작** (혼자서도 시작할 수 있어요).
4. 끝낼 때는 터미널에서 `Ctrl + C`.

## 3. GitHub에 올리기

Render는 GitHub 저장소에서 코드를 가져가 배포합니다. 먼저 저장소를 만듭니다.

### 방법 A. 웹 화면에서 올리기 (가장 쉬움)

1. <https://github.com> 에 로그인합니다 (계정이 없으면 가입).
2. 오른쪽 위 **`+`** → **New repository**.
3. 이렇게 입력합니다.
   - **Repository name**: `temu-tesla` (원하는 이름이어도 됩니다)
   - **Public / Private**: 아무거나 (Private 도 Render 에 연결할 수 있습니다)
   - ⚠️ **"Add a README file", ".gitignore", "license" 는 모두 체크하지 마세요.** (이미 들어 있습니다)
   - **Create repository** 클릭.
4. 비어 있는 저장소 화면에서 **`uploading an existing file`** 링크를 누릅니다.
5. 압축 푼 **프로젝트 폴더를 열고, 그 안의 모든 파일과 폴더를 선택**(`Ctrl+A` / `⌘+A`)해서 업로드 화면으로 끌어다 놓습니다.
   - 폴더 자체(`temu-tesla`)를 끌어다 놓지 말고 **안에 있는 것들**을 올려야 저장소 맨 위에 `package.json` 이 보입니다.
   - 파일이 약 60개라서 웹 업로드 한도(한 번에 100개) 안에 들어옵니다.
   - `node_modules` 폴더가 있다면(2단계를 했을 때 생김) **올리지 마세요.**
   - `.gitignore` 는 숨김 파일이라 선택이 안 돼도 괜찮습니다.
6. 업로드가 끝나면 아래의 **Commit changes** 클릭.
7. 저장소 첫 화면에 `client`, `server`, `shared`, `tools`, `package.json`, `README.md` 가 **바로** 보이면 성공입니다. (`temu-tesla` 폴더 하나만 보이면 한 겹 더 들어간 것이니, 아래 "문제 해결"의 *Root Directory* 항목을 보세요.)

### 방법 B. 명령어로 올리기 (git 을 아는 분)

```bash
cd temu-tesla
git init
git add .
git commit -m "Temu Tesla"
git branch -M main
git remote add origin https://github.com/내아이디/temu-tesla.git
git push -u origin main
```

## 4. Render에서 배포하기 (무료 Web Service)

1. <https://render.com> 에 접속 → **Get Started** → **GitHub 계정으로 로그인**하는 것이 가장 쉽습니다.
2. 대시보드에서 **`+ New`** → **Web Service** 를 고릅니다.
3. **Build and deploy from a Git repository** (또는 "Source Code")를 고르고 **Next**.
   - GitHub 저장소 목록에서 `temu-tesla` 를 고르고 **Connect**.
   - 저장소가 안 보이면 "Configure account" 를 눌러 Render 가 해당 저장소를 읽을 수 있게 허용하세요.
4. 설정 화면에서 **아래 표대로** 입력합니다.

| 항목 | 입력값 |
|---|---|
| **Name** | `temu-tesla` (주소가 `https://temu-tesla.onrender.com` 처럼 됩니다. 이미 쓰는 이름이면 다른 이름) |
| **Region** | `Singapore` (한국에서 가장 가까움) |
| **Branch** | `main` |
| **Root Directory** | **비워 둠** |
| **Runtime** (또는 Language) | `Node` |
| **Build Command** | `npm install` |
| **Start Command** | `npm start` |
| **Instance Type** | `Free` |
| *Advanced* → **Health Check Path** | `/health` |
| *Advanced* → Environment Variables (선택) | `NODE_VERSION` = `22` |

5. 맨 아래 **Create Web Service**(또는 Deploy Web Service) 클릭.
6. 로그 화면에서 `npm install` 이 끝나고 `[Temu Tesla] 서버 시작: ...` 이 보인 뒤 **Your service is live** 가 뜨면 완료입니다. (처음엔 몇 분 걸립니다.)
7. 화면 왼쪽 위의 주소(`https://....onrender.com`)를 눌러 게임이 뜨는지 확인합니다.

> Render 화면은 가끔 바뀌어서 버튼 이름이 위와 조금 다를 수 있습니다. 핵심은 **Node / `npm install` / `npm start` / Free** 네 가지입니다.

### 더 쉬운 방법: render.yaml (Blueprint)

저장소에 `render.yaml` 이 들어 있어서, 대시보드의 **`+ New` → Blueprint** 에서 저장소를 고르면 위 설정이 자동으로 채워집니다. 4번 표를 직접 입력하기 귀찮을 때 쓰세요.

### 무료 플랜 주의사항

- **약 15분 동안 아무도 접속하지 않으면 서버가 잠듭니다.** 다시 접속하면 깨어나는 데 보통 30~60초(가끔 더) 걸립니다. 이때 게임 화면에 **"서버를 깨우는 중…"** 이 표시되고, 서버가 깨어나면 자동으로 메뉴로 넘어갑니다.
- 방(room)은 서버 메모리에만 있어서 **서버가 잠들거나 다시 배포되면 모든 방이 사라집니다.** 친구들과 시작하기 직전에 한 번 접속해서 서버를 깨워 두면 좋습니다.
- 코드를 GitHub에 다시 올리면(Commit) Render가 자동으로 새로 배포합니다.

## 5. 친구와 함께 하기

친구에게는 **① 게임 주소(`https://....onrender.com`)** 와 **② 방 코드(알파벳 4글자)** 두 가지를 알려주면 됩니다.

1. **방장**: 주소 접속 → 이름 입력 → **방 만들기** → 로비 위쪽에 **방 코드 4글자**가 나옵니다. (**코드 복사** 버튼으로 복사해서 메신저에 붙여넣으세요.)
2. **친구들**: 같은 주소 접속 → 이름 입력 → 방 코드 입력(대소문자 상관없음) → **입장**.
3. 친구들은 **준비 완료**를 누릅니다. (방장은 자동으로 준비 상태)
4. 인원이 **1명 · 2명 · 4명**이면 방장의 **게임 시작** 버튼이 켜집니다. **3명이면 시작할 수 없고** "3명은 플레이할 수 없습니다. 1, 2, 4명이 되어야 시작할 수 있어요" 안내가 나옵니다. (한 방에 최대 4명)
5. 3초 카운트다운 후 출발! 각자 맡은 키가 화면 오른쪽 아래 **"내 담당 키"** 에 표시됩니다.
6. 도중에 누가 접속이 끊기면 **30초 동안 일시정지**합니다. 그 사이 자동으로 다시 연결을 시도하고, 안 되면 같은 탭에서 새로고침(`F5`)하세요. 30초 안에 돌아오면 같은 자리에서 이어서 하고, 못 돌아오면 로비로 돌아갑니다.
7. 도착하면 시간과 사망 횟수가 나옵니다. **다시 하기**를 누르면 로비로 돌아갑니다.

### 누가 어떤 키를 맡나요?

입장한 순서대로 맡는 칸이 정해집니다 (방장이 첫 번째).

| 인원 | 맡는 키 |
|---|---|
| **1명** | 전체 8키 `Q W A S E R D F` |
| **2명** | 1번 = **왼쪽** `Q A E D` / 2번 = **오른쪽** `W S R F` |
| **3명** | ❌ 시작 불가 |
| **4명** | 1번 = **좌측 앞** `Q E` / 2번 = **우측 앞** `W R` / 3번 = **좌측 뒤** `A D` / 4번 = **우측 뒤** `S F` |

자기가 맡지 않은 키는 눌러도 서버가 무시합니다.

## 6. 조작법

| 키 | 하는 일 |
|---|---|
| `Q` `W` `A` `S` | **바퀴** (좌앞 · 우앞 · 좌뒤 · 우뒤). 누른 바퀴만 구르기 때문에 한쪽만 누르면 차가 그쪽으로 돕니다. 지면에서만 동작하고 연료를 쓰지 않습니다. |
| `E` `R` `D` `F` | **제트 배출구** (좌앞 · 우앞 · 좌뒤 · 우뒤). 누른 모서리에서 위로 분사합니다. 켜진 개수만큼 연료가 빨리 닳습니다. 차를 기울여서 앞으로 날아가세요. |
| `Shift + R` 또는 `Backspace` | **자폭 부활** — 0.7초 누르고 있으면 폭발하고 마지막 체크포인트에서 다시 시작합니다. (`R` 은 배출구 키라서 `Shift` 를 함께 눌러야 합니다.) 끼었을 때 쓰세요. |
| `C` | **시점 전환** — 기본은 **그란 투리스모식 뒤쪽 추격 시점**, 한 번 더 누르면 탑뷰 |
| `Esc` | 설정 (시점 · 그래픽 품질 · 음량) |
| `F11` | 전체화면 |

- 한글 입력 상태여도 키 **위치**로 인식하므로 그대로 눌러도 됩니다. 키가 안 먹으면 게임 화면을 한 번 클릭하세요.
- 차 그림자·바닥 링·고도 막대가 화면에 나와서 얼마나 떠 있는지 가늠할 수 있습니다.

### 규칙 요약

- **연료**: 배출구 1개당 초당 7% 소모 (1개만 켜면 약 14초, 4개 모두 켜면 약 3.6초). 배출구를 안 누르고 있으면 충전됩니다 (지면 초당 8%, 공중은 절반). 0%가 되면 꺼지고 5%가 찰 때까지 다시 켤 수 없으며, 20% 이하면 경고가 뜹니다.
- **고도**: 배출구 4개를 풀로 켜면 약 40m 근처까지 올라가고, 그 위로는 힘이 줄어듭니다.
- **폭발**: **도로 바닥 외에는 무엇이든** 닿으면 폭발합니다 (벽, 장애물, 다른 차, 도로 밖으로 떨어지는 것 포함).
- **부활**: 폭발 후 2.5초 뒤 **마지막 체크포인트**에서 연료 100%로 시작하고, 2초 동안 무적입니다.
- 연료 충전 발판이 구간 곳곳에 있습니다. 비행 구간은 연료 100%로 충분히 넘을 수 있게 설계했습니다.

### 맵 (10구간, 총 9,000m)

| # | 구간 | 거리 (m) |
|---|---|---|
| 1 | 튜토리얼 거리 | 0 ~ 600 |
| 2 | 시내 교통 혼잡 | 600 ~ 1,500 |
| 3 | 공사장 | 1,500 ~ 2,400 |
| 4 | 고가도로 | 2,400 ~ 3,300 |
| 5 | 네온 야간 거리 | 3,300 ~ 4,200 |
| 6 | 공업 / 가스 지구 | 4,200 ~ 5,100 |
| 7 | 강 위의 다리 | 5,100 ~ 6,100 |
| 8 | 지하 터널 | 6,100 ~ 7,000 |
| 9 | 마천루 협곡 | 7,000 ~ 8,000 |
| 10 | 피날레 | 8,000 ~ 9,000 |

각 구간마다 체크포인트가 4개씩 있습니다 (총 40개). 이론상 가장 빠른 완주는 약 15분 30초이고 (사망·장애물 대기 시간 제외한 하한 추정), 보통은 훨씬 오래 걸립니다.

## 7. 문제 해결

| 증상 | 해결 |
|---|---|
| **"서버를 깨우는 중…" 이 오래 지속** | 무료 플랜이 잠들어 있던 것입니다. 보통 1분 안팎, 길면 2분 정도 기다리세요. 그래도 안 되면 `F5` 새로고침 → Render 대시보드 **Logs** 에 빨간 오류가 있는지 확인. |
| **Render 배포(Build)가 실패** | Logs 에서 `package.json` 을 못 찾는다는 메시지가 보이면 파일이 한 겹 안쪽 폴더에 올라간 것입니다. Render 설정의 **Root Directory** 에 그 폴더 이름(예: `temu-tesla`)을 넣고 다시 배포하거나, GitHub 에서 파일을 맨 위로 옮겨 다시 올리세요. |
| **화면이 검거나 "three" 관련 오류** | Build Command 가 `npm install` 인지 확인하세요. 서버 로그에 `[경고] node_modules/three 가 없습니다` 가 보이면 설치가 안 된 것입니다. |
| **"그 코드의 방이 없습니다"** | 코드를 다시 확인하세요. 서버가 그 사이 잠들었다 깨어났다면 방이 사라졌을 수 있으니 방장이 새로 만들어야 합니다. |
| **"이미 게임이 진행 중인 방입니다" / "방이 가득 찼습니다 (최대 4명)"** | 이미 시작한 방에는 들어갈 수 없고, 한 방에는 최대 4명까지입니다. 게임이 끝나 방이 로비로 돌아온 뒤에 들어오세요. |
| **3명인데 시작이 안 돼요** | 설계 사양입니다. 1·2·4명만 시작할 수 있습니다. 한 명이 나가거나 한 명을 더 데려오세요. |
| **키가 안 눌려요** | 게임 화면을 한 번 클릭한 뒤 눌러 보세요. 입력창(이름·코드)에 커서가 있으면 키가 글자로 들어갑니다. |
| **화면이 끊겨요** | `Esc` → **그래픽 품질**을 낮추거나 "프레임이 떨어지면 자동으로 낮추기"를 켜세요. 다른 탭·프로그램을 끄면 도움이 됩니다. |
| **소리가 안 나요** | 브라우저 정책상 화면을 한 번 클릭하거나 키를 누른 뒤부터 소리가 납니다. 설정의 음소거도 확인하세요. |
| **도중에 연결이 끊겼어요** | 30초 안에 새로고침(`F5`)하면 같은 자리로 돌아옵니다. |

그래도 안 되면 브라우저에서 `F12` → **Console** 탭의 빨간 글자를 복사해서 알려 주세요. 원인을 훨씬 빨리 찾을 수 있습니다.

## 8. 개발자용 정보

### 폴더 구조

```
temu-tesla/
├─ package.json          의존성: express, socket.io, three(0.170.0)  / engines: node >=18.19
├─ render.yaml           Render Blueprint (선택)
├─ server/
│  ├─ index.js           Express(정적 파일 + /health) + Socket.IO 서버
│  ├─ room.js            방/로비/준비/재접속(30초 일시정지) 관리
│  └─ game.js            서버 권위 게임 루프 (60Hz 물리, 약 30Hz 스냅샷 전송)
├─ shared/               서버와 브라우저가 함께 쓰는 코드 (같은 파일이라 항상 일치)
│  ├─ config.js          물리·연료·규칙 상수 (CFG)  ← 튜닝은 여기서
│  ├─ physics.js sim.js  차량 강체 물리, 바퀴/배출구/충돌/연료
│  ├─ collision.js obstacles.js world.js  충돌(OBB·SAT)과 시간 함수로 움직이는 장애물
│  ├─ keys.js            인원수별 키 배분
│  └─ maps/              city.js(맵 조립) + lib.js(MapBuilder) + secA/B/C(10구간) + city.fuel.js(비행별 필요 연료, 자동 생성)
├─ client/               브라우저 (three.js 는 /vendor/three 로 서버가 내려줌)
│  ├─ index.html style.css main.js net.js input.js ui.js audio.js debug.js
│  └─ render/            엔진·카메라(chaseCam)·도시·차량·이펙트·절차적 텍스처 (외부 이미지/모델/오디오 파일 없음)
└─ tools/                검증 도구 (아래)
```

- 장애물 중 움직이는 것은 **서버 시간 T 의 순수 함수**라서 서버와 브라우저가 따로 계산해도 같은 위치가 되고, 네트워크로는 차량 상태만 보냅니다.
- 이미지·3D 모델·소리 파일이 전혀 없습니다. 텍스처는 캔버스로, 소리는 Web Audio 로 코드가 직접 만듭니다.

### npm 스크립트

| 명령 | 설명 |
|---|---|
| `npm start` | 서버 실행 (`PORT` 환경변수가 없으면 3000) |
| `npm test` | 네트워크 없이 도는 전체 점검 묶음 (import 검사 → 카메라 → 클라이언트 스모크 → 봇 테스트 → 맵 검증). `npm install` 없이도 실행됩니다. |
| `npm run validate` | 맵 검증 (아래) + `shared/maps/city.fuel.js` 다시 생성 |
| `npm run bot-test` | 서버를 직접 띄우고 가상 접속자(봇)가 실제 Socket.IO 로 방 생성 → 시작 → 입력 → 재접속 → 도착까지 시험 (`npm install` 필요, 약 1분) |

- `node tools/bot-test.js http://localhost:3000` — 이미 떠 있는 서버(예: 배포한 Render 주소)에 대고 시험할 수도 있습니다. 시험용 방이 만들어졌다 사라질 뿐 데이터는 남지 않습니다.
- `node tools/bot-test.js --inproc` — 네트워크 없이 같은 프로세스에서 가짜 소켓으로 빠르게 시험합니다.

### 맵 검증 (`tools/validate-map.js`)

서버와 같은 물리로 **자동조종 프로그램**(`tools/autopilot.js`)이 8개 키로 모든 비행 구간(43개)을 직접 날아 보고, 필요 연료의 1.3배가 100% 이하인지 확인합니다. 그 밖에 정적/동적 장애물의 통과 가능성, 충전 발판 간격, 한 번 만땅으로 갈 수 있는 한계, 이론상 최단 완주 시간(15분 이상)을 점검합니다. `--fast`(일부만), `--no-write`(`city.fuel.js` 를 덮어쓰지 않음) 옵션이 있습니다.

> `shared/config.js` 의 물리 값(질량·추력·연료 등)이나 맵을 바꿨다면 **반드시 `npm run validate` 를 다시 실행**하세요. 비행별 필요 연료가 달라질 수 있습니다.

### 개발 모드 (`?debug`)

주소 뒤에 `/?debug` 를 붙여 접속한 뒤 **방을 만들면** 그 방에서만 개발 도구가 켜집니다: 구간별 순간이동, 무적, 충돌 박스 표시, 자유 카메라, 연료 채우기, 다음 체크포인트로 이동, FPS/지연 표시. 일반 주소로 만든 방에서는 서버가 개발 명령을 무시합니다.

### 그 밖의 도구

| 파일 | 설명 |
|---|---|
| `tools/test-camera.mjs` | 추격 카메라가 실제 물리 궤적(주행·조향·이륙·회전·고공)을 따라갈 때 차가 항상 화면 안에 구도에 맞게 들어오는지 수치로 확인 |
| `tools/smoke-client.mjs` + `tools/fake-three/` | 가짜 three.js 로 맵 전체의 렌더링 코드를 실행해 예외/NaN 이 없는지 확인 (실제 GPU 렌더링 검증은 아님) |
| `tools/check-imports.mjs` | 모든 JS 모듈의 import/export 이름이 맞는지 정적 검사 |
| `tools/phys-lab.mjs` | 물리 튜닝 실험용 스크립트 |

## 9. 알려진 한계 (솔직하게)

- **실제 서버·실제 GPU로는 실행해 보지 못했습니다.** 이 게임을 만든 환경에는 인터넷이 없어서 `npm install` 을 할 수 없었기 때문에, 서버 로직은 가짜 소켓 + 스텁 서버로, 화면 코드는 가짜 three.js · 소프트웨어 렌더링 · 브라우저의 셰이더 컴파일 검사로 확인했습니다. 따라서 **실제 조명·블룸·텍스처가 의도대로 보이는지, 몇 fps 가 나오는지는 첫 실행 때 직접 확인**이 필요합니다. 문제가 있으면 콘솔 오류 문구와 함께 알려 주세요.
- 연료 설계는 자동조종 프로그램 기준입니다. 사람의 실제 플레이는 더 어렵거나 쉬울 수 있습니다.
- 최단 완주 시간(약 15분 30초)은 "완벽한 플레이"를 가정한 하한 추정입니다.
- 거리별 LOD 와 피사계 심도(DoF)는 구현하지 않았습니다 (대신 300m 단위 청크 스트리밍과 안개로 먼 곳을 가립니다). GPU 인스턴싱은 파티클에만 적용했습니다.
- 추격 카메라는 벽·터널 천장·바닥에 파고들지 않게 제한하지만, 머리 위 구조물이나 장애물과의 충돌 처리는 하지 않습니다.
- `package-lock.json` 은 포함하지 않았습니다 (패키지를 내려받을 수 없어서 만들지 못함). `npm install` 이 `^` 범위 안의 최신 버전을 설치하고, three.js 만 0.170.0 으로 고정되어 있습니다.
- 무료 Render 플랜은 잠들기 때문에, 방은 서버가 재시작되면 사라집니다 (DB 를 쓰지 않습니다).
